## 二、性能优化类

### R1. main bundle 拆包（✅ 2026-09-03）

- **现状**：`vite build` 报告 main chunk **969KB（gzip 318KB）**，超 500KB 警告门槛。根因：同步导入 CodeMirror 6 全家桶（`editor.ts`）、KaTeX（`latex.ts`）、`marked`+`dompurify`（`preview.ts`）全部进入主 chunk。mermaid 已是动态 import 的正面范例。

- **方案**：`vite.config.mjs` 加 `build.rollupOptions.output.manualChunks`，按 vendor 拆：`codemirror` / `katex` / `marked+dompurify`；编辑/预览在首屏都必需，故不做懒加载，只做独立缓存分块。

- **结果**：主 chunk 969KB → 61KB（gzip 22KB）；按需 mermaid 仍走动态 import（兜底 vendor 3MB 不阻塞首屏）

### R2. 大文档渲染分档防抖（✅ 审查 P1-3 已落地）

- **路径**：`frontend/src/main.ts:previewDelay`

- **分档**：≤16K 16ms（≈一帧）、64K 120ms、256K 250ms、>256K 400ms

- **配合**：`preview.ts` 顶层块缓存 + 增量水合

- **R2 状态更新**：2026-09-03 复核发现 R2 已被"审查 P1-3"覆盖，移除该条独立待办。

## 三、健壮性类

- **路径**：`frontend/src/latex.ts:isTooHeavy`

- **覆盖**：

  - 公式超 8KB → 降级（恶意/粘贴失误）

  - 99999em / 99999pt 等异常长度单位 → 降级

- **测试**：`latex.test.ts` 新增 8 闸门 + 1 反向用例，66 通过 0 失败

## 五、工程化类

### R8. CI 接入（✅ 2026-09-03）

- **路径**：`.github/workflows/ci.yml`

- **任务**：

  - go-test：三平台（linux/windows/macos） + race + 覆盖率

  - frontend-test：tsc --noEmit + 单测（LITEMD\_TEST=all）

  - npm-audit：>= high 拦截

  - build：仅 v\* tag 触发，跨平台产物归档

### R9. E2E 失效断言处理（✅ 已收口 2026-09-21）

- **收口方式**：sprint1 于 v0.2.11 重写为 v3 版（走 `__litemd__bindings` 注入），实测 15/15 恢复有效；sprint2/3/5 断言全部失效且覆盖内容早已由 sprint4~11 补充，直接删除，`e2e/SPRINT-LEGACY-README.md` 随之删除（其"降级归档"标注已失真）

- **原计划**：sprint12 迁移或删/合无效脚本——实际以更小代价完成，无需 sprint12

### R10. 测试框架迁移 vitest（⏳）

- **现状**：`scripts.test` 用 `tsx` 跑自研 bootstrap；`test:unit` 非默认全量（需 `LITEMD_TEST=all`）

- **方案**：迁移 vitest + jsdom；`test:unit` 默认跑全量

- **预期效果**：测试与开发/构建工具链统一，报告与 watch 体验提升

- **触发**：独立排期（R9 已收口，不再依赖 sprint12 合并顺带）

### R11. navGuard 缓冲优化（⏳ 无瓶颈不重构）

- **现状**：navGuard 经 `httptest.Recorder` 全量缓冲再拷贝，主 chunk \~1MB 双份内存（TECHNICAL §8.1）。按"无瓶颈不重构"未改，属已知限制

- **方案**：仅当 R10（vitest 迁移）触碰该文件时顺带用流式写替代全量缓冲

- **预期效果**：消除双份内存；因无实测瓶颈，非紧急
