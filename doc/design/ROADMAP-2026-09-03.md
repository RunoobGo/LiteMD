## 二、性能优化类

### R1. main bundle 拆包（priority: P2）

- **现状**：`vite build` 报告 main chunk **969KB（gzip 318KB）**，超 500KB 警告门槛。根因：同步导入 CodeMirror 6 全家桶（`editor.ts`）、KaTeX（`latex.ts`）、`marked`+`dompurify`（`preview.ts`）全部进入主 chunk。mermaid 已是动态 import 的正面范例。

- **方案**：`vite.config.mjs` 加 `build.rollupOptions.output.manualChunks`，按 vendor 拆：`codemirror` / `katex` / `marked+dompurify`；编辑/预览在首屏都必需，故不做懒加载，只做独立缓存分块。

- **预期效果**

  - 冷启动主 JS 解析/求值时间下降（单文件求值 + 首屏关键块优先）。

  - HMR 与增量构建缓存友好，改预览不重编编辑块。

  - 为将来 Web/E2E（dev.html 走 vite 服务）铺垫按需加载。

- **注意**：Wails 本地磁盘加载，单发传输非瓶颈，收益集中解析与构建流程，属低成本正向改进。

### R2. 大文档渲染线性化（priority: P2）

- **现状**：`preview.ts:renderMarkdown` 每次键入走「公式提取 → marked → DOMPurify → link 加固 → 公式还原」全同步管线（`preview.ts:L112-L130`），长文档未发现节流/debounce。

- **方案**：渲染调度加防抖 + 首屏分片（requestIdleCallback/分块渲染首 100 块），预览与编辑滚动同步保持现有 data-line 锚点机制。

- **预期效果**：高千行文档输入不卡顿；预览滚动同步更稳。

## 三、健壮性类

### R3. 逃逸 maxSize 的命令加闸门（priority: P2，沿用待办）

- **现状**：`latex.ts` 的 LaTeX 经 KaTeX 渲染，`\raisebox` 等命令可逃逸 `throwOnError/maxSize` 限制撑爆 DOM（P2 待办）。

- **方案**：在提取公式处对危险命令（`\raisebox`、`\scalebox`、`\resizebox` 等尺寸类、长度单位注入）设白/黑名单闸门。

- **预期效果**：恶意或异常公式不再影响布局/性能；测试矩阵补用例。

### R4. 图片插入 markdown 转义（priority: P2，沿用待办）

- **现状**：`md-escape.ts` 图片插入的 alt/URL 未完整转义，含特殊字符会破坏链图片义。

- **方案**：对 alt 内 `[ ]`、URL 内空格/`（）`等做规范转义；补单测。

- **预期效果**：粘贴含特殊字符路径/标题后图片语义正确。

## 四、功能开发类

### R5. macOS Finder 双击打开（priority: P1，真实链路缺口）

- **现状**：`mac.Options.OnFileOpen` 未配置（`main.go`），macOS 双击 .md 打开链路失效，且 `main.go` 相关注释过时（P1 待办）。

- **方案**：配置 `OnFileOpen` 回调 → IPC 通知前端打开指定文件；同步更正注释；补交互验证。

- **预期效果**：macOS 最常用「双击打开」入口恢复可用，用户体验补齐。

### R6. `.mkdn` 文件关联注册（priority: P2，沿用待办）

- **现状**：仅注册 md/markdown/mdown/mkd；`.mkdn` 未关联。

- **方案**：构建清单增加 `.mkdn` 扩展名注册（后端 `fileio`/关联逻辑处核对一次）。

- **预期效果**：`.mkdn` 文件在系统打开方式中可选 LiteMD。

### R7. 字号 / 偏好持久化（priority: P2，沿用待办）

- **现状**：前端不消费 `GetConfig/SetConfig`，主题在 localStorage，**字号不持久化**（TECHNICAL §8.1）。

- **方案**：接入 `GetConfig/SetConfig` 或统一 localStorage，持久化字号与编辑偏好；补前端测试。

- **预期效果**：设置跨会话保留，设置项闭环。

### R12. 路线图：外部文件变更监控 / 自动更新（priority: P3）

- **现状**：目录监控先前用户决策取消；自动更新模块 2026-08-31 移除（e64af52，CHANGELOG 已勘误）。

- **方案（仅供路线图评估）**：外部变更监控走「前端活跃标签 3s 指纹比对 + 手动刷新」，避免常驻目录扫描；自动更新如需要可基于版本线增量恢复。

- **预期效果**：为将来协作编辑与分发升级保留扩展位，评估成本后再行。

## 五、工程化类

### R8. CI 接入（priority: P1，沿用待办）

- **现状**：`.github/` 暂无 CI 配置；`npm audit`、自动测试、覆盖率均未纳入流水线。

- **方案**：新增 Go（`go test ./... -race`）+ 前端（`tsc + 单测 + npm audit`）两阶段 CI。

- **预期效果**：依赖 CVE、回归、错误文案契约（`TestErrorTextContractForFrontend`）等在合并前置拦截。

- **预期覆盖率**：核心业务逻辑单测覆盖 >85%（当前基线与 >80% 目标）。

### R9. E2E sprint 断言修复（priority: P2，沿用待办）

- **现状**：`e2e/` sprint1/2/3/5 历史脚本断言失效（dev.html + mocks 环境变化）。

- **方案**：逐套对齐新接口与选择器。

- **预期效果**：回归脚本恢复可信，发布前可一键体检主流程。

### R10. 测试框架迁移 vitest（priority: P3，沿用待办）

- **现状**：`scripts.test` 用 `tsx` 跑自研 bootstrap；`test:unit` 非默认全量（需 `LITEMD_TEST=all`）。

- **方案**：迁移 vitest + jsdom；`test:unit` 默认跑全量。

- **预期效果**：测试与开发/构建工具链统一，报告与 watch 体验提升。

### R11. navGuard 缓冲优化（priority: P3，延续 S6 结论）

- **现状**：navGuard 经 `httptest.Recorder` 全量缓冲再拷贝，主 chunk \~1MB 双份内存（TECHNICAL §8.1）。按「无瓶颈不重构」未改，属已知限制。

- **方案**：仅当 R10（vitest 迁移）触碰该文件时顺带用流式写替代全量缓冲。

- **预期效果**：消除双份内存；因无实测瓶颈，非紧急。
